# Data dictionary

## Run inventory

`per_run.csv` has 2,520 rows. `(Problem, Algorithm, Repeat)` is the unique run key. `Seed` is the actual integer seed; repeats do not reuse a seed within the same problem/method. Different algorithms have different historical seed slots. `Seconds` is the measured whole-call elapsed time and `SecondsPerIteration = Seconds / 200`. `ActualPopulation` distinguishes native MOEA/D's three-objective size 91 from the configured request 100.

`IGD` and `HV` are the reported postprocessed indicators; `FrontSize` counts unique nondominated points. `SourceFile` is a filename only, retained for provenance. The original full MAT snapshots are not redistributed in this compact archive.

## Final objective matrices

Open `final_objectives/ZDT1.mat` (or another problem) in MATLAB. Fields follow `F_MOHOA_r01`, `F_NSGA3_r10`, `F_MOHOA_NoCauchy_r03`, etc. Matrices retain the original final `result.F` rows, including duplicate/dominated members if returned by an implementation. They are not prefiltered display fronts. For indicator or C-metric reproduction, first retain the unique nondominated points.

For ZDT/DTLZ, columns are `(f1, f2[, f3])`. For MK, columns are **`(Cmax, Energy, TotalWorkload)`**, corresponding to hours, kWh and hours under the reporting convention. There are 110 fields in each benchmark-function file and 120 in each MK file.

`MK10_MOHOA_decisions.mat` contains fields `X_MOHOA_r01` through `X_MOHOA_r10`. Each decision row matches the same row in `final_objectives/Mk10.mat`. The first half is the machine-selection component and the second half the operation-sequencing component used by the unchanged common decoder. The archived operations table is the direct source for the three paper Gantt charts.

## Reference fronts

Each `reference_fronts/<problem>.mat` contains `R` (raw reference points), `Lower`, `Upper` and `HVReference`. Normalize both the obtained front and `R` as `(F - Lower) / (Upper - Lower)`, replacing a span no larger than `1e-12` by 1. Do not clip. The HV reference is a vector of ones.

Benchmark references are the exact sampled analytical sets used for the paper. MK reference sets are the nondominated union over eight main methods and four ablations, ten repeats each. They are empirical, not certified true Pareto fronts. Adding algorithms/runs would require regenerating the pooled reference and all affected MK indicators.

## Tables and figure inputs

- `tables/all_summary.csv`: mean, sample standard deviation, median, type-7 linear quartiles, and IQR of every retained method/problem/indicator.
- `tables/functions_*` and `tables/MK_*`: main comparison, ablation, runtime and statistical tables. Family definitions are in `../docs/EXPERIMENT_PROTOCOL.md`.
- `tables/MK_C_metric.csv`: strict Pareto dominance coverage in both directions, paired by repeat index for reporting, averaged over the ten repeats. This is not a paired-seed statistical test.
- Representative runs are actual runs closest to the ten-run mean final HV, with ties resolved by repeat number. Numerical `Figure` labels in exported plot tables reflect their creation-stage numbering; identify plots by problem and algorithm, rather than relying on those labels as final manuscript numbers.
- `tables/MK10_operations.csv`: criterion, 1-based machine/job/operation, start, end. Machine IDs without eligible operations retain blank rows in the plots. `MK10_machine_times.csv` supplies processing, counted idle and last-completion times.
- `tables/MK10_extreme_objectives.csv`: the three extremes from the same representative MOHOA run (repeat 9). These are not three single-objective optimizations.
- `tables/MK_makespan_reference.csv`: exact best-known reference snapshot, best/mean MOHOA makespan and gap values used in the comparison. It concerns makespan alone.

All processing/idle powers are author-specified experimental inputs. `experiment_settings.json` retains the entire original 20-entry power vectors; only the first 15 entries are needed by the largest included MK instances and are listed in `power_parameters.csv`. Workload weights are all 1. No power sensitivity study is included.

Full generation histories, end RNG states and final decision matrices of other methods are omitted to keep the upload small. They can be regenerated by the supplied search code; they are not needed to recompute the final-front indicators and statistical tables.
